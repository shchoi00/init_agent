# Codex customization map

설정을 잘 쓰려면 모든 내용을 `AGENTS.md`에 넣지 않고 지속 범위와 실행
방식에 맞는 수단을 선택해야 합니다.

| 수단 | 넣을 내용 | 넣지 않을 내용 |
|---|---|---|
| 현재 prompt | 이번 작업의 목표, 문맥, 제약, 완료 조건 | 모든 세션에 필요한 규칙 |
| 전역 `AGENTS.md` | 개인의 판단·소통·검증 원칙 | 특정 저장소 경로와 명령 |
| 저장소 `AGENTS.md` | 구조, canonical 명령, 검증, 금지사항 | 개인 취향과 다른 저장소 규칙 |
| nested `AGENTS.md` | 특정 subtree에만 적용되는 규칙 | 저장소 전체 규칙의 반복 |
| `config.toml` | model, reasoning, sandbox, approval, MCP 등 | 연구 방법론을 설명하는 장문 |
| Skill | 반복되는 하나의 작업 절차 | 아직 반복되지 않은 가상 workflow |
| MCP/plugin | 저장소 밖의 최신·private 정보와 action | 정적인 설명 또는 기본 shell 접근 |
| hook/test/linter | 기계적으로 판정 가능한 invariant | 애매한 연구적 판단 |
| subagent | 독립적이고 병렬화 가능한 제한된 역할 | 여러 agent의 동시 코드 수정 |

## AGENTS.md

전역 파일은 개인의 operating principles를 담습니다. 저장소 파일은 해당
코드베이스의 실제 사실과 명령을 담습니다. 더 가까운 디렉터리의 지침이
나중에 적용됩니다.

짧고 정확한 지침이 긴 백과사전보다 낫습니다. 중요한 상세 지식은 별도
문서로 두고 `AGENTS.md`에서는 읽어야 할 위치만 안내합니다.

## Skills

같은 작업을 여러 번 수행하면서 입력, 순서, 결과물, 검증 기준이 안정됐을
때 만듭니다. 아직 반복 workflow가 없다면 만들지 않는 것이 정상입니다.

Skill 후보가 되는 신호:

- 같은 긴 prompt를 반복해서 사용함
- 같은 순서의 명령과 검증을 반복함
- 같은 종류의 실수를 여러 세션에서 교정함
- 결과물 형식이 명확하고 재사용 가능함

## MCP와 plugins

외부 시스템의 정보가 필요할 때만 추가합니다. GitHub 이슈·PR, 개인 논문
라이브러리, experiment tracker처럼 저장소 밖에서 계속 바뀌는 정보가
명확한 사용 사례입니다.

단지 “유용해 보인다”는 이유로 여러 MCP를 미리 설치하지 않습니다. 먼저
어떤 수동 반복을 제거할지 정하고, 가능하면 읽기 전용 권한으로 시작합니다.

## Subagents

서브에이전트는 역할 이름을 많이 만드는 것보다, 다음 조건을 만족하는
독립 작업에 제한하는 것이 좋습니다.

- 결과를 명확하게 합칠 수 있음
- 같은 파일을 동시에 수정하지 않음
- 탐색, 비교, 테스트, 로그 분석처럼 경계가 분명함
- 추가 token과 coordination 비용보다 병렬화 이익이 큼

특정 분야 이름만 붙인 제3자 agent pack은 기본 설치하지 않습니다. 실제
작업에서 반복적으로 분리가 필요한 역할이 확인된 뒤 최소한으로 정의합니다.

## 개선 루프

```text
실패 관찰
  → 최초 원인 분류
  → 자연어 판단 규칙이면 AGENTS.md
  → 반복 절차이면 Skill
  → 외부 정보 부족이면 MCP/plugin
  → 기계적 invariant이면 test/linter/hook
  → 한 번뿐이면 현재 prompt
```

한 번에 여러 규칙을 바꾸지 말고, 실제 실패 하나에 작은 변경 하나를
적용한 뒤 다음 작업에서 효과를 확인합니다.
